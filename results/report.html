2指标定义及理由

从业务方 4 个模糊需求中提炼出 5 个可量化评估指标：

指标业务需求量表权重选择理由
M1 准确性准确1-50.25 错误信息直接误导用户操作，是回复质量基石
M2 有用性有用1-50.30 人工标注显示最高频问题是"正确但没用"，权重最高
M3 语气与共情语气好1-50.20 客服场景用户常带负面情绪，恰当共情提升感知
M4 无幻觉不瞎编0/10.10(否决) 编造信息直接损害用户权益，设为否决性指标
M5 主动服务有用(延伸)1-50.15 人工与自动回复最大差距：人工主动帮、自动推用户

指标优先级

  1. 无幻觉（最高）：编造信息直接损害用户权益，一旦出现总分上限降为50%
  2. 准确性（高）：错误信息误导用户操作
  3. 有用性（高）：不解决问题的回复无价值
  4. 主动服务（中）：影响用户感知但不直接造成损失
  5. 语气与共情（中）：影响体验但非核心诉求

7局限性讨论

  1. Mock 模式的评估主观性：预置评分基于人工分析，存在主观偏差。改进：接入真实 LLM API
  2. 业务上下文依赖：准确性评分依赖业务规则知识。改进：接入知识库
  3. 有用性评估的 case-by-case 差异：同一回复对不同用户有用性不同
  4. 语气评估粒度不足："礼貌"和"共情"难以用单一指标区分
  5. 幻觉检测覆盖有限：对微妙幻觉（过度承诺等）可能漏检
  6. 样本量限制：20条样本统计代表性有限，建议至少200条
  7. 缺乏多轮对话评估：未考虑上下文连贯性等
